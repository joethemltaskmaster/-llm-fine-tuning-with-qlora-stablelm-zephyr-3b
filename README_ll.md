# llama-2-7b-mini-ult-guanaco/

The **final fine-tuned LoRA adapter**. This folder name is `FineTuneConfig.new_model`; `train.py` writes to it at the end of a run with `trainer.model.save_pretrained(config.new_model)`.

Everything here is **generated by a training run** and is git-ignored. Only this README is tracked.

> **Naming note:** the folder name says `llama-2-7b`, but the base model is `stabilityai/stablelm-zephyr-3b`. The name was inherited from the original notebook. To use a clearer one, pass `--new_model` when training, for example `--new_model stablelm-zephyr-3b-guanaco-lora`, and use the same value as `--adapter_path` at inference time.

## What training writes here

| File | Contents |
|---|---|
| `adapter_model.safetensors` | The trained LoRA weights (megabytes, not the multi-GB base model) |
| `adapter_config.json` | LoRA settings (`r`, `lora_alpha`, `lora_dropout`, target modules, task type) and the name of the base model the adapter belongs to |
| `README.md` | This file. PEFT **prepends a YAML metadata block** (`base_model`, `library_name`, `tags`) to it when saving; the text below the block is kept |

If your `peft` version also saves tokenizer or other metadata files, they appear alongside these.

> **Git note:** because PEFT edits this tracked README on save, `git status` will show it as modified after a training run. Either commit the metadata block (it is harmless) or discard it with `git checkout -- llama-2-7b-mini-ult-guanaco/README.md`.

## This is an adapter, not a standalone model

The folder holds only the difference learned on top of the base model. To use it you need the base model as well:

```python
from llm_finetune.inference import load_finetuned_model
model = load_finetuned_model("llama-2-7b-mini-ult-guanaco")  # loads the 4-bit base + applies this adapter
```

The adapter only works with the same base model and compatible LoRA settings it was trained with.

## Using it

Interactive testing:

```bash
python scripts/run_inference.py
```

One-off prompt:

```bash
python -m llm_finetune.inference --prompt "Tell me about operations research."
```

Pointing at a different folder:

```bash
python scripts/run_inference.py --adapter_path ./some/other/adapter
```

## Keeping it

Because this folder is git-ignored, back it up yourself once training finishes: copy it to Google Drive on Colab, or push it to the Hugging Face Hub with `model.push_to_hub("<your-username>/<repo-name>")`. Unlike `results/`, which can be thrown away after training, this is the one output you cannot regenerate without rerunning training.
