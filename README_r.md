# results/

Training output directory. This is `FineTuneConfig.output_dir` (default `./results`), passed to `TrainingArguments(output_dir=...)` in `train.py`.

Everything here is **generated by a training run** and is git-ignored. Only this README is tracked, so the folder exists after a fresh clone.

## What training writes here

| Path | Written when | Contents |
|---|---|---|
| `checkpoint-<step>/` | Every `save_steps` optimizer steps (default `25`) | A resumable snapshot, described below |
| `runs/` | From the first logged step | TensorBoard event logs (see `runs/README.md`) |

With the defaults (`save_steps=25`, `per_device_train_batch_size=1`, `gradient_accumulation_steps=4`) the 1,000-example Guanaco set is about 250 optimizer steps per epoch, so a one-epoch run should leave around ten checkpoints (`checkpoint-25` through `checkpoint-250`). `save_total_limit` is not set, so none are deleted automatically.

### Inside a `checkpoint-<step>/` folder

Because the model is wrapped with a LoRA adapter, a checkpoint holds the **adapter**, not the multi-GB 4-bit base model:

- `adapter_model.safetensors` and `adapter_config.json`: the LoRA weights and their configuration
- `optimizer.pt`, `scheduler.pt`, `rng_state.pth`: optimizer, LR-scheduler and RNG state needed to resume exactly
- `trainer_state.json`: step counter, loss history and logging data
- `training_args.bin`: the serialized `TrainingArguments`
- `README.md`: a model card auto-generated by PEFT
- Tokenizer files may also appear, depending on your `trl` / `transformers` versions

Exact file names can vary slightly between library versions.

## Using these files

Resume an interrupted run from the latest checkpoint:

```bash
./scripts/run_train.sh --resume_from_checkpoint auto
```

Or from a specific one:

```bash
./scripts/run_train.sh --resume_from_checkpoint ./results/checkpoint-100
```

Try an intermediate checkpoint without waiting for the run to finish:

```bash
python scripts/run_inference.py --adapter_path ./results/checkpoint-100
```

## Housekeeping

Checkpoints are the main thing that fills disk during training. Delete the ones you don't need once the final adapter has been saved (see `../llama-2-7b-mini-ult-guanaco/README.md`). On Colab, copy `results/` to Google Drive before the runtime resets, since the VM's disk is wiped.
